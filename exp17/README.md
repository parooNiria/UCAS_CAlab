# 实验前准备

## tlb转换流程：

（建议先看一下龙芯精简指令手册）

首先明确tlb是cpu的一部分。


1.判断翻译模式：看CRMD中PG和DA位（这个功能需要添加到cpu中，exp18完成），PG为映射模式，DA为直连模式

此时如果为映射模式，需要根据DMW寄存的内容判断当前访问是直接映射还是页表映射。

直接映射窗口的具体例子在手册上有介绍。

这个如果满足条件，会由cpu自己处理，不归tlb管

2.页表映射模式：

（在精简指令集中没有STLB和MTLB，此时TLB采用全相连的组织形式，极其简单）

（1）tlb表项结构（相比完整的指令集表项，此时的控制位大大减少）

一项对应两个虚页，分为比较部分和物理转换部分。

比较部分VPPN长度为（VALEN-13 ps: 13 = 4KB + 双页对应低位）

（2）例外

重填例外：独立例外入口，设置DA为1

页无效异常：分为取指，store，load

权限不合规异常

页修改异常：D为0

（3）相关CSR

两类：交互和遍历（以及重填异常）

（4）转换方式：

一个va -> 找tlb表项（需要E即有效还有asid等内容匹配） -> 找tlb表项内的的物理转换部分有效 -> 把对应的物理转换部分记住 -> 转换（在此过程可能报出一系列例外）

## 设计分析

（1）该模块需要同时有取指和访存两个转换能力

（2）具体转换：

输入： vppn,va_bit12(两个一起拼成虚拟地址)，asid用于进程匹配，（似乎没有权限的问题输入，这个是tlb会把对应的信息输出进行匹配）

输出： s_found(这个用于判断tlb重填异常)，s_ppn(用于产生最后的实际物理地址),s_ps（页大小），s_mat(权限)，s_d(修改异常)，s_v(页无效异常)

(3)需要支持TLBSRCH指令

使用CSR.ASID 和 CSR.TLBEHI 的信息去查询 TLB。如果有命中项，那么将命中项的索引值写入到CSR.TLBIDX 的 Index 域。

这个指令其实就是一个查找操作，因此可以复用访存指令的相关端口。这个可以不用特意实现

并且，由于这个指令查找的不是对应的tlb项中的内容，而是index，无法复用，因此需要加上一个s_index输出。

(4)支持TLBWR

由CSR.TLBIDX的Index域的值指定，填入CSR中相关信息到tlb

(5)支持TLBFILL

随机填入CSR中相关信息到tlb

为了支持上诉两个写操作，要专门有一个写通道。

包括信号：w_index 写地址...

(6)支持TLBRD指令

读index指示的对应信息，此时加上一个独立的读端口

(7)支持INVTLB指令

用于无效TLB中内容的指令，

格式 ：invtlb  op, rj, rk

含义：op操作类型（不同op无效掉的信息不一样），rj--asid，rk指定va。

此时的查找复用访存端口，但是需要有对应的op输入。

这样一共五个端口：取指端口，访存端口，读端口，写端口，再加上一个tlb失效指令端口.

## 总结

通过上述准备，可以看出，tlb就是单纯的一个寄存器组，其读取就是与cpu中寄存器读取类似，问题在于，它需要支持一系列的tlb设置指令。

有TLBSRCH指令（这条指令的实现不与普通的查找予以区分，只是将index送入cpu中，让cpu在需要的时候利用）。这个地方还需要送入是否找到对应表项的信息，通过s1_found表示。（其实与一半的查找没区别）

有TLBWR和TLBFILL，这两指令用于填写tlb，区别在于FILL的填入表项不是由cpu指定的。

对于这个写的内容,从指令集的角度上来看，从CSR中各种寄存器中获得，但是对于tlb直接使用cpu解析好的值即可。

（这个地方存在一个问题，即在指令集中定义了填写有效项和无效项的区别，以及随机填写表项）


有TLBRD指令。这个实现较为简单，直接读出对应的数据，至于指令集中定义的如果无效，需要设置对应寄存器的值为1等过程，由cpu自己实现。


有INVTLB指令，这个需要判断对应的op。

op有

0x0   清除所有页表项。
0x1   清除所有页表项。此时操作效果与op=0完全一致。
0x2   清除所有G=1的页表项。
0x3   清除所有G=0的页表项。
0x4   清除所有G=0，且ASID等于寄存器指定ASID的页表项。
0x5   清除G=0，且ASID等于寄存器指定ASID，且VA等于寄存器指定VA的页表项。
0x6   清除所有G=1或ASID等于寄存器指定ASID，且VA等于寄存器指定VA的页表项。

可以采取分开子匹配条件的方式予以匹配。

那么总结一下上述的实现：

一共四个通道加上invtlb_valid信号和op

对于读，写端口，用于支持对应的csr特权指令，根据送入的index值，读或者修改相应的tlb表项，invtlb复用写端口，此时需要一个对应的inv_match信号，在复用写端口时修改响应e(有效位)

对于取指和数据翻译端口，依据送入的va 和 asid进行匹配，再将对应的表项送出，此时需要match0和match1信号。

ps：在上述的所有地方，对于页大小对于匹配的影响没有提到过：

在精简指令集中，va {vppn，页内偏移}，当页大小不一样时，对于需要比对的vppn位数是不一样的，
此时有4KB（12）和4MB（22）两种页，4MB时只需要比对高10位即可，4KB需要比对全部，因此有如下的语句

(s0_vppn[18:9] == tlb_vppn[i][18:9])
                   && (tlb_ps4MB[i] || s0_vppn[8:0] == tlb_vppn[i][8:0])

对于物理地址的影响是此时的ppn是高位有效，但是在tlb中不需要予以区分，这个任务会交给cpu
