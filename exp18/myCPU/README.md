## 预备工作

(1)相关指令分析

1.TLBSRCH （这条读不是通过index去读的，请务必分清这一点）

使用CSR.ASID 和 CSR.TLBEHI 的信息去查询 TLB。（对应寄存器未实现）如果有命中项，那么将命中项的索引值写入到CSR.TLBIDX 的 Index 域，同时将CSR.TLBIDX的NE位置为0；如果没有命中项，那么将CSR.TLBIDX的NE位置为1。

此处查找是复用访存指令的的tlb端口查找，发生在ex级，那么就存在一个问题，即特权指令写入csr是发生在WB级，则在EX级查找，CSR.ASID 和 CSR.TLBEHI 可能会变，TLB中表项的值也可能在后两条指令中发生改变。

对于CSR.ASID 和 CSR.TLBEHI 可能会变，此时采用数据前递花销和收获不匹配，采用阻塞的方式实现。

对于可能由于TLBWR，TLBFILL，INVTLB引起的tlb表项改变问题。会在下面予以分析。

ps:这个地方没办法采用完全的阻塞，因为要在译码级才能得到指令类别，那么至少取出一条指令，不如采取标记重取法。

2.三条写tlb指令，TLBWR，TLBFILL，INVTLB指令。

对于前两条条指令，改变tlb是通过独立的写端口实现的，因此两条条指令可以自己决定在哪一级进行写操作。但是这两条指令也是需要使用csr来辅助实现写操作，也存在读寄存器相关的问题，因此安排在WB级是一个合理的安排。

麻烦的地方在于这三条指令的后续指令，与csr的某些写指令（修改CRMD中DA.PG。DMW0、DMW1和ASID寄存器）相类似的问题是，这些指令的执行是可能改变后续指令的映射关系，因此这条指令的后续指令是需要取消的，（这个地方如果像ID那样判断是否取消，开销太大了），而由于上述提到的没法完全阻塞的问题,因此此处采取的方式是继续流水，只是像异常处理那样，让后续的未在这些写指令执行前取出的指令不发生实际的效果，当这条指令进入WB级，取消前面的所有指令，并重取。这个地方的重取一定要在下一拍开始发生，与异常不一样。

这个地方还存在一个问题，即对于fill中，有一点描述模糊不清，即fill填入的表项是由硬件随机决定的。
干脆不分WR和FILL，全部使用INDEX来决定要写哪一项。

3.TLBRD

将CSR.TLBIDX 的Index 域的值作为索引值去读取TLB中的指定项。如果指定位置处是一个有效TLB表项，那么将该TLB项的页表信息写入到CSR.TLBEHI、CSR.TLBELO0、CSR.TLBELO1和CSR.TLBIDX.PS
中，且将CSR.TLBIDX的NE位置为0；如果指定位置处是一个无效TLB项，需将CSR.TLBIDX的NE位
置为1，且将CSR.ASID.ASID、CSR.TLBEHI、CSR.TLBELO0、CSR.TLBELO1 和CSR.TLBIDX.PS全置为
0。

对于这个读指令，与写指令类似，有专门的读通道，可以自由决定读的时机，但是为了方便，依旧设计在WB级，此处还有一个好处，这条指令需要写csr，可以同步进行。

由于此处的asid也是会被改变的，因此后续指令也有和写指令类似的问题，采取标记重取法。

4.INVTLB

这条指令与此前分析的不同，他是存在操作数的，这条指令可能比对三种信息，即G，ASID，VPPN

invtlb  op, rj, rk

op决定操作类型，rj的[9:0]位存放无效操作所需的ASID信息，rk中用于存放无效操作所需的虚拟地址信息。

由于他不需要使用csr辅助去写，并且需要对应的s1段口复用因此在EX级发生是比较合适的，至于可能改变tlb的前几条指令影响，有标记重取法避免了这一问题。这条指令也需要一个标记重取的措施，那么此时可以肯定的一点是复用异常的取消端口是不合理的。

ps：此时值得指出的是会对处理器产生影响的，现在还多了一个invalid

（2）虚实转换方式分析

在实现了上述的指令分析之后，在此处可以梳理一下如何借助tlb来实现虚实地址翻译。

首先明确，tlb就是一个单纯的寄存器，存了一些表项，cpu送入一个地址，tlb组合的给出一个物理地址，这个物理地址即是虚拟地址合理的对应。

此外，地址翻译是存在三种模式的（这一点务必先看指令集手册）

直接地址翻译，映射翻译分为tlb地址翻译和直接映射翻译。

因此，对于一个地址，可以做这么一个操作：

实现三个部件：直接翻译、直接映射翻译、tlb映射翻译，最后依据当前的条件做一个多路选择。这个就实现了MMU。

（3）MMU相关异常的实现

这个地方的操作就是利用tlb模块得到的一些辅助信息，和对应的生产出来的物理地址进行一些异常的判断（注意：这个地方会对前述已实现的异常产生一定的变化，例如对于之前的取指地址异常，之前是直接用对应的pc判断低两位的，现在应该使用翻译出的物理地址。）

此时有一个问题就是由精确异常的概念，发生异常的指令对应的那条指令要像没有执行过一样，因此如果地址错误，不应该发出对应的请求，但是在之前的实现中，if级采取的措施是就算存在指令地址错异常，也是会发送出去的，这个时候加入MMU，如果对应的指令地址发生了错误，就不应该发出对应的请求，需要予以改变。


至此，所有问题分析完毕，可以开始编写对应的代码了。
